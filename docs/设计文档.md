# 设计文档（中文）

## 1. 设计目标
- 提供清晰、可用的线路规划交互：选起点/终点 → 一键规划 → 地图与列表同步展示
- 算法与数据解耦：支持从 `edges.csv` 明确定义道路/连接关系，也支持按经纬度自动生成边作为兜底
- 可部署、可复现：`docker compose up -d --build` 一键运行

## 2. API 设计

### 2.1 健康检查
- `GET /api/health`
- 返回：`{ status: "ok", time: "..." }`

### 2.2 节点列表
- `GET /api/nodes`
- 返回：节点数组 `[{ id, name, lat, lng, type?, desc? }, ...]`

### 2.3 最短路径
- `GET /api/path?from=<id>&to=<id>&strategy=<distance|stops>`
- `strategy` 可选：`distance`（最短距离，默认）/ `stops`（最少经停）
- 成功返回：
  - `startId` / `endId`
  - `totalDistanceMeters`
  - `pathNodeIds` / `pathNodes`
  - `segmentDistanceMeters`
  - `strategy`（实际使用的策略）
- 失败返回：`{ error: "...中文错误信息..." }`

### 2.4 路线收藏
- `GET /api/favorites`：收藏列表（按创建时间倒序）
- `POST /api/favorites`：新建收藏
  - 请求体：`{ name, startId, startName?, endId, endName?, strategy, totalDistanceMeters, pathNodeIds, pathNodes, segmentDistanceMeters }`
  - 服务端生成 `id` 与 `createdAt`，返回 `201` 与完整记录
  - 校验失败返回 `400 { error: "..." }`
- `DELETE /api/favorites/{id}`：删除收藏；成功返回 `204`，不存在返回 `404`
- 收藏数据持久化在独立的 `favorite_routes` 表（路线节点以 JSON 快照存储），与公共图数据（`nodes` / `edges.csv`）完全隔离，收藏的增删不影响图数据

## 3. 前端交互设计

### 3.1 控制面板
- 起点/终点下拉选择（支持搜索）
- 规划策略选择（最短距离 / 最少经停）
- 交换起终点、清空选择
- 一键规划并展示总距离与路径节点列表
- 路线收藏：规划结果可命名保存（名称、起点、终点、策略、路线节点快照）
- 收藏列表：载入（恢复路线快照到地图与列表）、删除（需二次确认）
- 收藏持久化：优先走后端 `/api/favorites`；后端不可用时自动降级到浏览器 localStorage，刷新页面后仍可见

### 3.2 地图交互
- 渲染所有景点 Marker
- Marker Popup 支持“一键设为起点/终点”
- 规划成功后绘制路线 Polyline

## 4. 数据与容错设计

### 4.1 CSV 数据
- `nodes.csv`：必须存在且包含列 `id,name,lat,lng`（其他列可选）
- `edges.csv`：可选；至少包含 `from,to`；权重列支持：`distance_meters` / `weight_meters` / `distanceMeters` / `weightMeters`

### 4.2 容错策略
- 后端：`DataLoader` 对缺列/坏行进行跳过或给出明确的中文异常提示
- 前端：对节点 API 返回进行结构校验与清洗，避免脏数据触发运行时崩溃
- UI：ErrorBoundary 捕获不可预期异常并提示刷新重试

## 5. 性能与扩展
- 节点数量较小（景点级别）时，Dijkstra 在内存中运行即可满足交互性能
- 未来扩展点：
  - 引入真实道路网（大量边）时，可考虑启发式算法（A*）或预计算缓存
  - 为边增加更多权重维度（拥堵、票价、偏好等）
